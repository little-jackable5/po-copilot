BACKLOG PRODUIT

User stories

Transformez les besoins utilisateurs en stories structurées.

◈

Une bonne user story doit exprimer une valeur

Utilisez le format « En tant que… Je veux… Afin de… ». Si le rôle, le besoin ou la valeur ne sont pas précisés, PO Copilot les signalera plutôt que de les inventer.

QUALITÉ PRODUIT

Bugs

Documentez les anomalies sans inventer les étapes ou les résultats.

⚑

Un bug utile est reproductible et vérifiable

Décrivez le contexte, le résultat observé et le résultat attendu. Les informations absentes restent explicitement à compléter.

VALIDATION FONCTIONNELLE

Critères d'acceptation

Préparez des conditions simples et vérifiables.

☷

Privilégiez des critères observables

Chaque critère doit pouvoir être vérifié. Les règles métier inconnues sont présentées comme des questions à clarifier.

RECETTE FONCTIONNELLE

Cas de test

Préparez les étapes et les résultats attendus avant l'exécution.

✓

Une proposition n'est pas un test exécuté

PO Copilot prépare une base de travail. Le résultat obtenu et le statut doivent être renseignés lors de la recette réelle.
